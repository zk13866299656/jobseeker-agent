# 切片5（工具集扩展）端到端测试记录

日期：2026-08-13
被测功能：3 个记忆驱动工具（`job_match` / `resume_improve` / `mistake_review`）+ `Tool.execute` 接口加 `userId`

## 测试目标

验证三个关键点：

1. **工具触发**：说对应话术时，模型真的调用工具（界面出现「调用工具：xxx」），而不是自己编答案。
2. **读记忆**：工具输出带用户画像（技能 / 目标岗位），证明「工具 + 记忆」闭环打通。
3. **个性化产出**：匹配度表 / STAR 要点 / 复盘卡是工具确定性计算的，非模型瞎编。

## 测试方法

启动后端（`mvn spring-boot:run`）+ 浏览器打开 `http://localhost:8080`，观察 SSE 流式四段：**思考 → 调用工具 → 工具结果 → 回答**。

判断工具是否触发，就看有没有出现「调用工具：xxx」这一行——有这行才证明工具被真正执行，否则是模型绕过了工具。

## 测试步骤与结果

### ① job_match（岗位匹配）

说：

> 我想找 Java 后端的工作，帮我看看我适合哪个方向

结果：触发「调用工具：job_match」，工具结果输出各方向匹配度（按匹配度降序）+ 缺失技能清单。匹配度和缺失技能是工具按内置岗位库算出来的，不是模型编的。

### ② resume_improve（简历优化）

说：

> 帮我优化简历，我在学校做过一个图书管理系统，用 SpringBoot 和 MySQL 做的

结果：触发「调用工具：resume_improve」，工具结果输出 STAR 四段（情境/任务/行动/结果）简历要点，并带记忆里的技能（Java、SpringBoot 等）。

### ③ mistake_review（错题复盘）—— 初次未触发，踩坑

说：

> 这道题我答错了：HashMap 底层原理是什么？我当时只说了是用数组存的

结果：**未出现「调用工具：mistake_review」**，模型直接 `final_answer` 自己答了复盘（内容质量尚可，但工具没被调用）。

## 发现的问题：mistake_review 未触发

**现象**：界面无「调用工具：mistake_review」，模型绕过工具直接回答。

**定位**（两个原因叠加）：

1. **description 触发信号太软**：原文「针对用户答错的面试题生成结构化复盘框架」——工具只给空框架，正确思路还得模型自己补，模型觉得「直接答更省事」，倾向绕过工具。
2. **偶发 JSON 格式错误**：模型第一轮想调工具但输出 JSON 不合法，被系统纠正（思考字段出现「用户指出我的输出不是合法 JSON」），重试时改走 `final_answer`。

**修复**：强化 description，加「必须调用」+ 明确触发条件（commit `51f85dd`）：

> 当用户提到某道面试题答错了、做错了、不会做或要复盘错题时，必须调用此工具生成结构化错题复盘卡（题目/我的错误/正确思路/知识盲区/下次怎么做），再基于复盘卡补全正确思路

**复测**：重新说原话，触发「调用工具：mistake_review」，输出结构化复盘卡。

## 结论

切片5 三个工具 E2E 验证通过：都能被模型可靠调用、读记忆、产出个性化结果。mistake_review 的「触发信号偏软」问题已通过强化 description 修复。
